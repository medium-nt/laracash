# Дизайн: Починить распознавание кешбэка (Подход 1)

**Дата:** 2026-08-09
**Статус:** Утверждён пользователем
**Скоуп:** бэкенд-only (`app/Services/AiService.php`), UI ввода не трогается

---

## 1. Контекст

LaraCash — self-service: каждый пользователь ведёт свои карты и каждый месяц обновляет размеры кешбэка по категориям. Источник новых процентов — скриншоты из мобильных приложений банков (иногда — сайт/уведомления банка).

Для автоматизации уже есть распознавание скриншота через GigaChat (`AiService`), но пользователи называют его «кривым». Из анализа кода выявлены конкретные корневые причины:

- **Хардкод расширения `.jpg`** в `AiService::downloadFile()` (`app/Services/AiService.php:38`). Поле `$card->cashback_image` хранит полное имя с расширением (`5.png`), но `downloadFile` игнорирует его и ищет `{id}.jpg`. Для `.png`-скриншота `file_exists()` → `false` → возвращается пустая строка → GigaChat получает пустой `attachments` → распознавание молча возвращает пустоту.
- **Секрет GigaChat в коде** (`AiService.php:165`): Basic-ключ захардкожен прямо в `getToken()`. Утечка секрета в git.
- **В промпт не попадают `keywords`** (`AiService::getPrompt()`, строки 17-20): в инструкцию модели передаются только названия категорий (`pluck('title')`), а поле `keywords` (синонимы: «бензин заправка топливо» для АЗС) не используется. Модель маппит категории с экрана «вслепую» по названиям.
- **Строгий маппинг ответа** в `resources/views/cashback/card_edit.blade.php:63-64`: `collect($recognizedCashback)->firstWhere('category', $categoryName)` — строгое совпадение строки. Любое расхождение возвращённого имени с именем категории юзера теряет процент.
- **Молчаливая обработка невалидного ответа** (`AiService.php:145-148`): `json_decode()` содержимого ответа может вернуть `null` (модель отдала prose/markdown), это молча записывается в `cashback_json`, юзер не получает внятной ошибки.

## 2. Цель и скоуп

**Цель:** сделать распознавание скриншота надёжным — `.png` перестают падать, синонимы учитываются, проценты корректно подставляются в существующие категории, пустые ответы не маскируются успехом.

**Входит:**
- 5 правок в `AiService` + вынос секрета в конфиг.
- Юнит-тесты на новый fuzzy-метод.

**Не входит (YAGNI, отложено):**
- Переделка экрана ввода под мобилку / live-save (Подход 3).
- Общий глобальный справочник категорий вместо персональных (Подход 2, меняет data model).
- История/снапшоты кешбэка по месяцам.
- Подсветка «сомнительных» сопоставлений в UI.
- Удаление мёртвой JS-функции `autofillCategories` в `card_edit.blade.php`, откат `verify => false`, устранение дублирования `downloadFile` при 401-retry.

## 3. Текущее состояние (как работает)

- Загрузка скриншота: `CashbackController::downloadCashbackImage()` (`app/Http/Controllers/CashbackController.php:102-127`) сохраняет файл `{card_id}.{ext}` в диск `card_cashback_image`, пишет имя в `$card->cashback_image`, обнуляет `cashback_json`.
- Запуск распознавания: `CashbackController::recognizeCashback()` (`:138-145`) → `AiService::getRecognizedCashback()` → `recognizeGigaChat()` → результат в `$card->cashback_json`.
- Промпт: `getPrompt()` (`AiService.php:15-34`) берёт `Category::where('user_id', auth)->pluck('title')`.
- Подстановка в форму: `card_edit.blade.php:61-70` при `?fill_recognize=yes` строго ищет совпадение имени.
- Модель `Category` имеет поля `title`, `keywords` (строка синонимов через пробел), `user_id`. Дефолтные значения с keywords — в `app/Services/CategoryService.php:11-40`.

## 4. Решение — 5 правок

### Правка 1. Реальное расширение файла
`AiService::downloadFile()`:
- Путь: `storage_path('app/public/card_cashback_image/' . $card->cashback_image)` (вместо `'{id}.jpg'`).
- Если `cashback_image` пуст или файл не существует — лог + `return ''` (как сейчас).
- В `Http::attach()` третьим аргументом передавать `$card->cashback_image` (корректное имя с расширением для MIME), а не `'1.jpg'`.

### Правка 2. Секрет в `.env` (Tier 3)
- `config/services.php`: секция `'gigachat' => ['auth_key' => env('GIGACHAT_AUTH_KEY')],`.
- `AiService::getToken()`: читать `config('services.gigachat.auth_key')` вместо захардкоженного Basic-ключа.
- `.env` / `.env.example`: добавить `GIGACHAT_AUTH_KEY=` (в `.env` — реальный ключ, в `.env.example` — пусто).
- **Безопасность:** текущий ключ уже в истории git → пользователь ротирует его в личном кабинете Сбера (вне кода). Дизайн только убирает ключ из исходников.

### Правка 3. `keywords` в промпт
`getPrompt()`: вместо `pluck('title')` грузить категории с `title` и `keywords`, и формировать список вида «`title` (синонимы: keywords)». empty keywords — без скобок. Текст промпта и жёсткие правила сопоставления оставить без изменений.

### Правка 4. Fuzzy-постобработка ответа → каноничные имена (ядро)
Новый приватный метод `mapToUserCategories(array $recognized, int $userId): array`. На вход — распарсенный ответ GigaChat `[{category, cashback}, ...]`, на выход — тот же массив, где `category` заменён на **каноничное `title` категории юзера**, если найдено совпадение; иначе оставлен как есть.

Цепочка сопоставления для каждой строки `$recognized['category']` (нормализованное сравнение: `mb_strtolower`, `trim`):
1. Точное совпадение с `title`.
2. Точное совпадение с одним из токенов `keywords` (разбор `keywords` по пробелу) — то есть распознанное имя == синоним.
3. Вхождение: `title` категории содержится в распознанной строке ИЛИ распознанная строка содержится в `title`.
4. Нормализованное сходство через `similar_text` / `levenshtein` с порогом (процент сходства ≥ выбранного; конкретный порог зафиксировать в реализации и покрыть тестами).
5. Нет совпадения — оставить «сырую» строку (покажется в списке распознанных, но не подставится в инпут; текущее поведение сохранено).

Метод вызывается в `recognizeGigaChat()` после `json_decode` и перед записью в `cashback_json`. Категории юзера загрузить одним запросом (`Category::where('user_id', $userId)->get(['id','title','keywords'])`), кешировать по `user_id` в рамках вызова.

**Почему UI не трогаем:** постобработка делает `category` равной каноничному имени категории, поэтому существующий строгий `firstWhere('category', $categoryName)` в blade снова находит совпадение.

### Правка 5. Обработка пустых/невалидных ответов
`recognizeGigaChat()` после `json_decode`:
- Если результат не массив или пуст → лог в канал `ai_api` + `return false` (не сохранять `null` в `cashback_json`).
- `recognizeCashback()` в контроллере уже возвращает «Кешбек не был распознан» при `false` — юзер получит внятное сообщение вместо тишины.

## 5. Альтернативы (рассмотренные)

- **Подход 3 (мобильный UI + импорт текста):** переделать экран ввода под телефон, live-save, импорт скопированного текста с сайта банка. Не зависит от капризов AI, но не выбран на этом шаге.
- **Подход 2 (общий справочник категорий):** глобальные категории вместо персональных → точнее маппинг и консистентный публичный поиск. Меняет data model, дольше и рискованнее. Отложено.
- **UI-выбор категории из сырых строк:** вместо бэкенд-маппинга показывать распознанные строки и давать юзеру выбрать категорию из списка. Надёжнее, но требует правок UI (запрещено в выбранном скоупе). Рассмотреть, если точность правок 3+4 окажется недостаточной.

## 6. Последствия и риски

- **Главный риск:** правки 3+4 — best-effort на бэкенде; модель всё ещё может ошибаться на скриншотах с необычным форматом. **Обязательная проверка:** прогнать на 5–10 реальных скриншотах разных банков (Сбер, Т-Банк, Альфа) до и после. Если точность остаётся плохой — вернуться к UI-варианту (Подход 3), а не закручивать промпт дальше.
- Существующий формат `cashback_json` (`[{category, cashback}]`) сохраняется → обратная совместимость, миграция данных не нужна.
- Вынос секрета в `.env` не отменяет необходимость ротации уже утёкшего ключа.
- Не обещается «всё распознаётся» — обещается «`.png` и синонимы перестают теряться, плюс честная обработка пустоты».

## 7. Тесты (`laravel-test-generator`)

Юнит-тесты на `AiService::mapToUserCategories()` (вход: массив ответа + набор категорий юзера):
- точное совпадение `title` → каноничное имя;
- совпадение по `keywords` (синоним) → каноничное имя;
- совпадение по вхождению подстроки;
- совпадение по сходству строк выше порога;
- отсутствие совпадения → строка без изменений;
- несколько распознанных строк, часть сопоставлена, часть нет.

HTTP-вызовы GigaChat в тестах мокаются (реальный API не дёргается). Категории/карты — через фабрики или ручное создание (по конвенциям проекта).
