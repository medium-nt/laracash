# Редизайн меню распознанных кешбэков в ботах (TG + MAX)

**Дата:** 2026-08-13
**Статус:** Proposed (ожидает ревью)
**Scope:** UI/UX редактора распознанных кешбэков в `AbstractBotConversationService`

---

## 1. Контекст и проблема

После распознавания кешбэков (с фото или текста) бот показывает редактор: текстовый список пунктов и под каждым пунктом **одну строку из трёх узких inline-кнопок**:

```
[✅/🆕 title %][🗑][📝]
```

Пользователь жалуется: кнопки узкие, название категории не видно/обрезано, неудобно.

Клавиатура и текст редактора строятся **в одном месте** — `AbstractBotConversationService` (`buildEditorKeyboard` line 755, `buildEditorText` line 703, `renderEditor` line 989). Оба адаптера — `TelegramConversationService` и `MaxConversationService` — наследуют их без перекрытия. Значит, редизайн делается один раз и работает на обеих платформах.

`callback_data` (TG) / `payload` (MAX) — плоские строки (`edit:0`, `del:1`, `note:0`), формируемые через платформенный `makeButton()`. Новые плоские форматы автоматически работают на обеих платформах без правок адаптеров.

## 2. Цели и вне-scope

**Цель:** широкая кнопка-категория во всю ширину; тап разворачивает аккордеон с раздельной правкой полей (Название / Процент / Примечание / Удалить / Свернуть).

**Вне-scope (явно исключено по решению пользователя):**
- Подтверждение удаления — 🗑 удаляет сразу, как сейчас.
- «Шапка» текста (имя карты, кол-во, легенда) — текст не меняется.
- Confirm для «Заменить (удалить старые)» — глобальные кнопки без изменений.
- Сортировка пунктов (✅/🆕) — порядок как есть.

## 3. Текущее состояние (краткая карта)

- **Клавиатура** `buildEditorKeyboard(array $items)` (line 755): на каждый item один ряд из 3 кнопок (`edit:{i}` / `del:{i}` / `note:{i}`); плюс ряды `add`, `merge`, `replace`, `cancel`.
- **Текст** `buildEditorText(array $items)` (line 703): «Проверь распознанное:» + нумерованные `✅/🆕 title — %`.
- **Роутинг** `handleCallback()` (line 259): матчинг `str_starts_with` по `callback_data` → ветки `edit:{i}`, `del:{i}`, `note:{i}`, `add`, `merge/replace/cancel` и др.
- **State machine:** `idle`, `await_card`, `await_photo`, `await_confirm`, `await_edit`, `await_add`, `await_note`. Состояние хранится в Cache-массиве (`state()` line 1028 / `setState()` line 1040), TTL 1800с.
- **Правка сейчас:** `edit:{i}` → состояние `await_edit` + `index`; ввод одной строкой парсится `parseItem()` (title+percent+mcc).
- **Структура item:** `['title'=>string, 'percent'=>float, 'category_id'=>?int, 'mcc'=>string]`.
- **Мэтчинг категории:** `attachCategory()` (line 865) через `CategoryMatcher`.
- **Тесты:** Reflection-проверки `buildEditorKeyboard`/`buildEditorText` — TG:647/667/775/826, MAX:343/361/439/472. Обновляются в паре с кодом.

## 4. Решение

### 4.1. Раскладка клавиатуры

`buildEditorKeyboard(array $items, ?int $active = null): array` — добавляется параметр `active` (индекс развёрнутого пункта, `null` = всё свёрнуто).

**Свёрнутое состояние (по умолчанию):** каждый item — один широкий ряд.

```
[ ➕ Добавить категорию ]
[ ✅ Супермаркеты          5% ]
[ 🆕 Рестораны            10% ]   ← тап = cat:1
[ ✅ Такси                 7% ]
[ 💾 Сохранить (добавить к старым) ]
[ ♻️ Заменить (удалить старые) ]
[ Отменить ]
```

Лейбл широкой кнопки: `{▶|▼} {✅|🆕} {title} {percent}%` — префикс-стрелка `▶` (свёрнуто) / `▼` (активен, развёрнуто) даёт явный индикатор состояния каждого пункта. Title обрезается до 30 символов с `…`. Физически title не содержит `\n` (гарантировано `parseItem`).

**Визуальная разметка развёрнутого пункта (итерация 3 — вариант A, по итогам реального тестирования):** inline-кнопки TG/MAX центрируют текст лейбла, не дают left-align/цвета/фона — выровнять значения полей «лесенкой» внутри кнопок ненадёжно (разная длина меток → самой длинной достаётся меньше всего точек; неточная emoji-ширина; точка ýже символа). Поэтому значения полей переносятся в **текст** сообщения, а клавиатура развёрнутого пункта содержит только **кнопки-действия** во всю ширину:
- широкая кнопка `cat:{i}` несёт префикс-стрелку `▶` (свёрнуто) / `▼` (активно); название **активной** категории — ВЕРХНИМ регистром (`mb_strtoupper`), свёрнутые — обычный регистр (inline-кнопки не поддерживают жирный/курсив, регистр — единственный канал выделения кнопки);
- под строкой развёрнутого пункта в `buildEditorText(array $items, ?int $active)` дописывается блок значений (метка: значение) с древовидными префиксами: `  ├ Название: {title}` / `  ├ Процент: {percent}%` / `  └ Примечание: {mcc ?: '(пусто)'}`;
- клавиатура активного пункта: `✏️ Изменить название` (`edt_t:{i}`) / `％ Изменить процент` (`edt_p:{i}`, fullwidth ％) / `📝 Примечание` (`note:{i}`), затем ряд `🗑 Удалить` (`del:{i}`) + `✖ Свернуть` (`cat:{i}`).

При развёрнутом пункте (`active !== null`) глобальные кнопки (`add`/`merge`/`replace`/`cancel`) скрыты, чтобы не создавать шум при редактировании поля; доступны после ✖ Свернуть (`active = null`). Активная строка пункта в тексте выделяется жирным (`<b>`); подпункты — plain (курсив `<i>` убран: при нём древовидные `├`/`└` выглядят некрасиво). Оба транспорта шлют HTML. `callback_data` от раскладки не зависят и не меняются. Хелперы `labelWidth`/`padLabel` (leader-dots) удалены как мёртвый код.

**Развёрнутый пункт (active = 1):** под активной широкой кнопкой появляются кнопки-действия; значения полей печатаются в тексте под строкой пункта; остальные пункты остаются свёрнутыми.

```
ТЕКСТ:
Проверь распознанное:

1. ✅ Супермаркеты — 5%

2. ▼ ✅ Рестораны — 10%        ← активен
   Название: Рестораны
   Процент: 10%
   Примечание: (пусто)

3. ✅ Такси — 7%

КЛАВИАТУРА:
[ ➕ Добавить категорию ]
[ ▶ ✅ Супермаркеты 5% ]
[ ▼ ✅ Рестораны 10% ]
[ ✏️ Изменить название ]
[ ％ Изменить процент ]
[ 📝 Примечание ]
[ 🗑 Удалить ] [ ✖ Свернуть ]
[ ▶ ✅ Такси 7% ]
[ 💾 Сохранить (добавить к старым) ]
[ ♻️ Заменить (удалить старые) ]
[ Отменить ]
```

Тап по уже активной широкой кнопке (`cat:{i}` где `i == active`) — сворачивает. Тап по другой — сворачивает текущий и разворачивает новую (аккордеон). `✖ Свернуть` — эквивалент `cat:{active}`.

Лейблы полей показывают **текущие значения**: `Название: {title}`, `Процент: {percent}%`, `Примечание: {mcc ?: '(пусто)'}`.

### 4.2. Callback-формат

| Действие | callback_data | Поведение |
|---|---|---|
| Тап по пункту (разворот/сворот) | `cat:{i}` | toggle `active` в state, перерисовка редактора |
| Правка названия | `edt_t:{i}` | → `await_edit` + `{index:i, field:'title'}` |
| Правка процента | `edt_p:{i}` | → `await_edit` + `{index:i, field:'percent'}` |
| Примечание | `note:{i}` | без изменений → `await_note` + `{index:i}` |
| Удалить | `del:{i}` | без изменений, удаляет сразу |
| Свернуть | `cat:{active}` | toggle (тот же формат) |
| Глобальные `add`/`merge`/`replace`/`cancel` | без изменений | — |

Ветку `edit:{i}` в `handleCallback` заменяем на `cat:{i}` (старый формат из UI уходит; `parseItem` остаётся для `await_add`).

**Graceful для уже отправленных клавиатур:** `edit:{i}` сохраняется как алиас `cat:{i}` (toggle разворота) — чтобы тап по старой клавиатуре, оставшейся от прошлой сессии до деплоя, не падал, а разворачивал пункт по новой схеме.

### 4.3. State machine

**Новых состояний не вводится.**

- `await_confirm` + extra `{active: ?int}` — разворот хранится как индекс в extra, состояние то же. Перерисовка клавиатуры — без смены состояния.
- `await_edit` + extra `{index: int, field: 'title'|'percent'}` — параметризуем существующее состояние флагом `field`. Ввод обрабатывается в существующем блоке `handleMessage` (line 205–243) с ветвлением по `field`.
- `await_note` — без изменений (`index` в extra).

**Переходы:**

| Из → В | Триггер |
|---|---|
| `await_confirm` → `await_confirm` | `cat:{i}` (toggle `active`, перерисовка) |
| `await_confirm` → `await_edit` | `edt_t:{i}` / `edt_p:{i}` |
| `await_confirm` → `await_note` | `note:{i}` |
| `await_confirm` → `await_confirm` | `del:{i}` (удалить + перерисовка) |
| `await_edit` → `await_confirm` | текстовый ввод поля (с `{active:index}` — пункт остаётся развёрнут) |
| `await_note` → `await_confirm` | текстовый ввод / `/skip` (с `{active:index}`) |

### 4.4. Правка полей и мэтчинг категории

Ветвление по `field` в обработчике `await_edit`, парсинг вынесен в приватные методы:

- **`parseTitle(string $text): ?string`** — trim, вырез `\r\n\t`, обрезка до длины колонки (как `sanitizeNote`). Валидация: непустое.
- **`parsePercent(string $text): ?float`** — первое число (`\d+(?:[.,]\d+)?`), нормализация запятой→точка. Валидация: `>= 0` (процент 0 допустим = «нет кешбэка»; сохранение пропускает `<= 0`, как сейчас в `CashbackImportService`).

Применение поля к item (`applyTitle()` / `applyPercent()`):
- `applyTitle(i, title)` — меняет `title`, затем **пересопоставляет категорию** через `attachCategory()` (см. допущение §7.1): обновляет `category_id` и каноничный `title`.
- `applyPercent(i, percent)` — меняет только `percent`, `category_id` не трогается.
- `await_note` — меняет `mcc` (существующее поведение).

### 4.5. Крайние случаи

- **0 пунктов** после распознавания — редактор не показывается (существующее поведение «ничего не распознано»).
- **1 пункт** — широкая кнопка показывается свёрнутой как обычно; разворот доступен, но не принудительный (единое поведение, меньше ветвлений).
- **Длинный title** — на широкой кнопке обрезается до 30 символов с `…`; в поле «Название» — полный title.
- **Невалидный ввод поля** — бот отвечает пояснением и остаётся в `await_edit`/`await_note` (без смены состояния), пункт остаётся развёрнут после возврата.
- **Тап `cat:{i}` при уже активном `i`** — сворачивает (`active = null`).
- **`del:{i}` при развёрнутом `i`** — пункт удаляется, `active` сбрасывается в `null` (корректный индекс после удаления).

## 7. Допущения и открытые вопросы

### 7.1. ❓ Мэтчинг категории при правке названия
Принято: переименование → пересопоставление категории через `attachCategory()` (название = ключ мэтчинга), `category_id` и каноничный `title` обновляются; маркер может смениться ✅↔🆕. **Не подтверждалось пользователем.** Альтернатива — сохранять старый `category_id` при правке title (риск рассинхронизации title и категории). Если неверно — правка одной строки в `applyTitle`.

### 7.2. Процент 0
Допустим как «нет кешбэка»; при сохранении пункт с `percent <= 0` пропускается (`CashbackImportService`, существующее поведение). Не блокируем ввод 0 на этапе правки.

## 8. Альтернативы и последствия (из архитектурного сомнения)

**Альтернатива A — отдельные состояния** (`await_edit_title`, `await_edit_percent`): чище по SRP, но дублирование логики `handleMessage` и +2 состояния. Отвергнуто ради DRY.

**Альтернатива B — под-меню на отдельном сообщении**: изоляция пункта, но плодит сообщения → ломает cleanup на MAX (нельзя удалять сообщения пользователя) и усложняет «вернуться». Отвергнуто.

**Последствия выбранного подхода (параметризация `await_edit` + `field`):**
- `handleMessage` для `await_edit` получает ветвление по `field` — компенсируется выносом парсинга/применения в отдельные методы.
- `buildEditorKeyboard` получает параметр `active` — меняет сигнатуру; все точки вызова `renderEditor` обновляются.
- Разворот хранится в state extra `active` — переживает TTL состояния (30 мин), как и сам `items`; если state протухнет — редактор перерисуется свёрнутым (корректный fallback).
